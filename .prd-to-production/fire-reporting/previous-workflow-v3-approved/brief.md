# Scene2Real — England incident reporting, proposed v3

For English fire and rescue personnel, extend the existing local report preview into an accurate incident-report preparation tool. Match the authorised national FaRDaP form and output for the applicable service/version. Preserve the working workbench, Cosmos evidence, planning and simulator. This proposal is unapproved; production, GitHub and the deployed site remain untouched.

**P-report-preview** — existing `/?run=:runId#report` state at `/`: select one run → prepare form → review supported evidence and blank fields → preview → download/print. The official source determines sections and output length; the earlier one-page demo limit does not constrain the official form.

- **R-standard:** Obtain and pin the authoritative active FaRDaP specification, field dictionary, codes, conditional/repeating/mandatory rules, validation examples and exact output template before implementing official fields. Preserve its labels, types, units, ordering and output parameters. The public 2012 IRS material is historical, not a current substitute. Establish service/version applicability and whether the national contract defines a printable form or requires an authorised service-specific layout.
- **R-mapping:** Document every official field's definition, applicability and supported Scene2Real source. Fill only where the source establishes the defined fact; distinguish machine suggestions from accepted incident facts. Keep unavailable fields blank. Do not substitute zero, No, unknown or not-applicable unless the specification and evidence support that answer. Blank required fields mean an incomplete draft.
- **R-evidence:** Retain one run's source identity and synthetic/cached/unknown provenance. Fire descriptions and clip-relative samples are machine observations for review. Run/report creation times are not incident times; template zones/coordinates are authored assumptions. Do not infer cause, severity, casualties, damage, address or official incident times from them.
- **R-outcome:** Current instructions and suppression/exposure/success metrics describe simulation only. They cannot populate actual FRS actions or real extinguishment/outcome fields. Real robot telemetry is absent; such fields stay blank until a suitable source exists. Keep any simulation material clearly separate from the official form.
- **R-integrity:** Build the form from one current snapshot; preserve source and review provenance. Reset, reanalysis, reconfirmation, source changes or run switching must invalidate dependent content. Reject stale/in-flight results from another run, including at export.
- **R-export:** Match the supplied official output format/layout and all applicable fields without clipping; preserve blanks. Escape untrusted text and exclude credentials, private URLs and local paths. An incomplete or unverified draft must not claim to be an accepted official submission.
- **R-preserve:** Implement locally and additively after source, brief and mockup approval. Do not replace the planner, alter Cosmos processing or measured simulator outputs, introduce inference calls for the report, submit records externally, commit, push or deploy.
- **R-verify:** Compare fields/codes/conditions and exported output against authoritative fixtures. Cover complete and incomplete records; honest success/failure simulation separation; blank versus No/zero; synthetic evidence; source refresh/reset/reconfirmation; cross-run races; text escaping; and readable multipage printing where the template requires it.

Source dependency: current FaRDaP materials have not been obtained. The user has no access. Request them through MHCLG or a participating FRS; no enquiry has been sent. Until supplied, exact form conformance and official-form mockups cannot be established. See `fire-reporting/research/national-standard.md` and `fire-reporting/specification-request.md` when available.

Proposed decision for approval: official values derived from vision require explicit field-level operator acceptance, recorded separately from the original suggestion. The supplied specification may impose additional review requirements. Authentication, external submission and operational robot control are outside this change.
